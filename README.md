# LLM Code Energy Analysis

## An Empirical Analysis of Energy Consumption in LLM-Generated vs Human-Written Code

### Overview
This research project investigates whether code generated by Large Language Models (LLMs) differs in energy consumption compared to human-written code. We benchmark 20 programming tasks across 4 categories, comparing three solution variants:

- **Human-Optimized**: Expert-level, performance-tuned code
- **Human-Typical**: Correct, readable, mid-level developer code  
- **LLM-Generated**: Characteristic LLM output patterns (verbose, over-engineered, correct)

### Research Questions
- **RQ1**: Is there a statistically significant difference in energy consumption between LLM-generated and human-written code?
- **RQ2**: Does the energy gap vary across programming task categories?
- **RQ3**: Does code complexity correlate with energy consumption differences?

### Task Categories (20 tasks)
| Category | Tasks |
|----------|-------|
| Sorting & Searching | Mergesort, Binary Search, Top-K, String Sort, Median |
| String Processing | Anagram Groups, Regex Match, Palindrome, Run-Length Encoding, Levenshtein |
| Numerical Computation | Matrix Multiply, Prime Sieve, Fibonacci, Newton Sqrt, Statistics |
| Data Transformation | CSV Parse, JSON Transform, Dedup, Group Aggregate, Flatten |

### Measurement Methodology
- **Metrics**: CPU time, wall-clock time, peak memory, energy estimate (CPU-time × TDP)
- **Statistical rigor**: 10 measurement iterations + 2 warmup per solution, Mann-Whitney U tests, Cohen's d effect sizes, 95% confidence intervals
- **Isolation**: Each run in a separate subprocess with `python3 -I`
